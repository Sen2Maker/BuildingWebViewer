# v1.4.5 validation — 2026-10-13

## Confirmed fixes

- The native diagnostics recovery button cleared the active signed web update and selected APK-bundled assets. It has been removed. Returning to projects uses the save-aware handler when available.
- Native lifecycle dispatch no longer calls `Capacitor.triggerEvent` while the bridge is absent. Startup diagnostics also record JS warnings independently of successful project-home startup.
- Native routing blocks the browser hub. An Android-only early shell intercepts toolbar home links before asynchronous project restore completes. The browser website is unchanged.
- Diagnostic log writes are debounced onto an IO executor. Gaussian sort transfers recycle their output buffers after copying into persistent GPU upload staging memory. Data population, sorting rules and quality presets are unchanged.
- Every future release must include a same-version complete APK. Signing and publication checks reject reuse of an older APK.

- `python3 scripts/check.py`: all source regression suites, generated bundles and HTML links pass.
- `node --test mobile/test-app-shell.mjs`: native save-aware home interception, no duplicate handler call and unchanged browser links pass.
- `python3 mobile/prepare.py`: 22 Android scripts parse as ES2017; compatibility fallbacks and offline project-home checks pass.
- Android debug APK and instrumentation APK compile; native unit tests pass, including route/lifecycle policy and diagnostic URL redaction.

Covers native project home, failure report, browser-hub redirection, removed recovery button, all five viewers' save-before-back flow, and actual Gaussian rendering/ten-second timing report retention.
- Full APK embeds v1.4.5 web assets; the release signer verifies all embedded web bytes, version code, pinned installer certificate, manifest signature and payload hashes before publication.

## Limits

The user's startup report has no GPU timing or continuous-interaction frame samples. Its redacted resource URL cannot identify the old 404 resource. No specific FPS improvement or complete elimination of device stutter is claimed. The Xiaomi Android 15/Adreno device still needs a same-dataset replay and a new ten-second rendering diagnostic. Emulator rendering validates behavior, not phone performance. The native diagnostics/lifecycle changes require this APK; a web-only update cannot remove a button compiled into the old APK.
